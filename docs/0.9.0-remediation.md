# Arpeggia 0.9.0 Remediation Tasks

This is the authoritative implementation ledger for the decisions in
`CONTEXT.md` and ADRs 0001–0007. Work proceeds top to bottom. Each scientific
change is a vertical test-first slice and must remain attributable to one
behavior.

## Confirmed public test seams

- Rust library functions and their returned records/DataFrames/scalars.
- Python functions exported from `arpeggia` and Python warnings/exceptions.
- CLI commands, stderr diagnostics, exit status, and serialized output.
- PDB/mmCIF input files at the parser boundary.
- Release manifests and workflows through static validation and lock/audit tools.

Tests target these seams. Private geometry and parser helpers are tested only
when no public observation can isolate a scientific boundary cheaply.

### Scientific correctness

- [x] Suppress intra-chain contacts only for Peptide-Adjacent Residues: same
      chain, continuous C--N geometry within the reference peptide-building
      distance, and no explicit chain break. Missing C/N evidence does not
      establish adjacency. Honor a PDB `TER` only when it follows a complete
      residue and matches that residue's name, chain, sequence number, and
      insertion code; reject mid-residue and mismatched breaks in coordinate-
      aware contact analysis. Keep `seqres` independent of `TER` validation.
- [x] Make histidine H-bond donor/acceptor typing respect HID/HSD, HIE/HSE,
      HIP/HSP, and explicit ring-hydrogen evidence for unresolved HIS.
      Hydrogen-free plain HIS may emit an ambiguous distance-only polar contact
      with a warning, but not a geometric hydrogen bond.
- [x] Normalize HID/HIE/HIP and HSD/HSE/HSP to canonical HIS only for SC
      atom-radius lookup so alias spelling does not select elemental fallback
      radii. Do not infer protonation from this normalization.
- [x] Seed residue SAP output from every selected supported residue so GLY and
      other zero-side-chain residues receive explicit zero-valued rows.
- [x] Emit Prepared-Input Diagnostics from full-atom SAP for hydrogen-free input

### Implementation and evidence order

Implement each scientific correction as a small vertical commit containing its
public regression test. Then normalize public error and model-selection
boundaries, stream the metadata parser and update CI/package constraints, and
remove confirmed dead SC machinery last. Do not mix behavior changes into the
cleanup commit.

The final release audit runs formatting, `prek` for every changed file, Clippy,
Rust tests and doctests, Python tests, `ty`, dependency audits, locked release
builds, per-wheel installation and smoke tests, the largest-mmCIF wall/RSS
comparison, and the matched-input SC, SASA, and SAP reference checks. Every
ledger item must cite direct code or command evidence, the final report must be
the only durable generated benchmark artifact, and the worktree must contain no
unexplained changes.

Performance candidates are developed in temporary worktrees from one baseline:
SC sorted-neighbor vectors alone, the `u8` group mask alone, and both changes
combined. Only a candidate with identical scientific output and a clear wall-
time or peak-RSS improvement is selected. Commit only the selected production
code, its correctness regressions, the reproducibility instructions, and the
final HTML evidence; discard the temporary candidate machinery.

Routine pull-request CI uses the small explicit-bond fixture and existing 6BFT
goldens. Full 2EAB contact and SC runs are a documented local release checkpoint,
not a routine CI job. The local fixture is fetched from the RustSASA test corpus
at commit `ad8ecd2237abd41291d39e7e5e7e6ad5bbcea2c7`, prepared with the pinned
Rosetta revision `597b55d6600c3939574ffee30a4469b26c3337bd` using the documented
empty protocol, and verified by recorded source and prepared-file SHA-256
digests before use.

After the gate passes on `feat/v0.9.0`, create `release/v0.9.0` from `master` and
select only the final production, regression-test, documentation, and release-
evidence commits. Re-run the audit on that assembled branch before merging it

## Measured decisions and explicit deferrals

The corrected release-mode H/L SC regression takes 0.19 seconds of test work;
five whole-command runs, including Cargo startup, measured 320.4 ± 6.5 ms.
Five release CLI runs of 1UBQ contact analysis plus CSV output measured
22.4 ± 0.2 ms. Those small workloads did not justify another spatial-index
layer. The post-audit work therefore reuses the existing `rstar` neighbor query
instead of adding an index, and tests compact post-query storage on the larger
2EAB workload. Streaming the contact candidate pipeline remains deferred until
a representative workload demonstrates a material benefit.

The following doubts remain recorded rather than silently dismissed:

- Corrected H/L SC is 0.725407 (directions 0.724196 and 0.726618) and matches
  the pinned `sc-rs` core with the same atom population. Its stock CLI reports
  0.714361 because its name-based hydrogen filter also removes the tyrosine
  oxygen named `OH`; that input-preparation discrepancy is not scoring drift.
- Arpeggia reproduces Rosetta legacy `SasaFilter` atom polarity, but the curated
  cross-tool benchmark confirms its Shrake–Rupley/ProtOr areas are not
  numerically equivalent to Rosetta's full-atom LeGrand areas. Standard SASA
  therefore remains the accepted heavy-atom Shrake--Rupley/ProtOr definition;
  its polar/hydrophobic labels match the Rosetta partition, not LeGrand areas.
- The heuristic histidine mode uses an intrinsic-pKa population prior. It is
  not a local-environment pKa predictor; inferred contacts stay potential.
- Single-conformer selection is deterministic but does not represent an
  occupancy-weighted ensemble.
- `bincode` (through Polars) and `paste` (through rust-sasa) are unmaintained
  according to RustSec, but have no reported vulnerability. Replacing either
  requires an upstream dependency change and is deferred. Two vulnerable
  `quick-xml` advisories are ignored only because Cargo locks them through
  optional Polars metadata while `cargo tree` proves neither `quick-xml` nor
  `object_store` is compiled in default or Python builds.

Per the evidence gates, `Vec3`, test fixtures, the public `Interactions` trait,
`StructurePreparation`, and the shared Python contract remain in place. Their
current use does not justify a compatibility-breaking or speculative rewrite.

Post-v0.9 development superseded the visibility portion of this decision. A
complete Rust reachability audit showed that `Vec3` was never externally
reachable and that `Interactions` had no publicly accessible Arpeggia
implementor. Their visibility was narrowed or removed without changing the SC,
Python, or CLI contracts; `StructurePreparation` remains crate-private and
shared.
